Technical description

Optimal input

One MP4 (H.264) cine loop per view. Put the apical four-chamber loop first, because Unity-GLS uses the first file and targets apical views (A4C, A2C, A3C). At least 16 frames per clip; a two-second loop at 30 fps is a practical minimum. Single-plane grayscale B-mode works best.

Do not concatenate different views into one file. PanEcho samples 16 consecutive frames, so a concatenated file produces clips straddling a view change, and Unity's seven context frames assume one continuous acquisition. Load each view as its own file.

Avoid colour Doppler, burned-in calipers or measurements, and screen recordings with overlays or dropped frames: these change what the network sees and sit outside the released preprocessing.

Optimal way to use it

Load the apical loop, plus any additional views as separate files. PanEcho runs four clips of 16 frames from each cine and averages clip predictions within a cine, then across cines, matching upstream study-level averaging. Two to three views is a good balance; four views means sixteen clips and a few minutes of frame extraction on a phone.

Unity-GLS runs eight temporal windows on the first cine using context frames at offsets −9, −3, −1, 0, 1, 3, 9. Shortening is (max − min) / max of the endocardial contour length across those windows.

PanEcho emits all forty tasks for whatever you supply; an emitted value does not prove the task was assessable from those views. Treat single-view studies, especially PLAX-only, as limited. GLS is learned regression, not speckle tracking, and wall-motion is a study-level probability rather than a segment map.

First use downloads PanEcho (168 MB) or Unity-GLS (268 MB) and caches it in the browser; later visits load from the device cache. Switching models releases the previous session.
