Technical description

Optimal input

One MP4 (H.264) cine per view, at least 16 frames per clip (about two seconds at 30 fps). Single-plane grayscale B-mode works best. Load each view as a separate file: clips are 16 consecutive frames, so concatenating views makes clips straddle a view change.

Avoid colour Doppler, burned-in calipers and screen recordings with overlays.

Optimal way to use it

Add the apical loop plus any other views. Four clips of 16 frames are taken from each cine and averaged within a cine, then across cines, matching upstream study-level averaging. Two to three views is a practical balance.

All forty tasks are emitted for whatever you supply; an emitted value does not prove the task was assessable from those views. GLS is learned regression, not speckle tracking. Wall motion is a study-level probability, not a segment map.

Model and source

Weights: huggingface.co/AnupamK/panecho-onnx (pinned 07d2bb2). Source: CarDS-Yale/PanEcho at commit 836c46e. ONNX opset 17, FP32, no retraining. PyTorch vs ONNX Runtime max absolute difference 6.19e-3.

Browser deviations: bilinear canvas resize rather than OpenCV INTER_AREA, assumed 30 fps when the container does not report it.
